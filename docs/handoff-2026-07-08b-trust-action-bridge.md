## 0. 한 줄 요약

"독자가 이걸 유의미한 결과로 못 받아들인다"는 피드백에서 출발해, **정직성 신호를 하나도
지우지 않으면서** 리포트가 스스로를 부인하지 않게 고쳤다. 사실오류 1건(LLM 도출 인터뷰
질문을 heuristic으로 표기)도 함께 잡았다. 샘플 리포트를 개편본으로 교체·배포 완료.
main = origin 동기, 359 테스트 키 없이 그린.

## 1. 상태 확인 먼저 (이 순서로)

```
git status -sb                       # main, origin 동기
npx vitest run --pool=threads        # 359 passed (55 파일). ⚠️ --pool=threads 필수
npx tsc --noEmit                     # 통과
npm run lint                         # biome 0 errors (⚠️ tail -1 금지 — 위쪽 에러 놓침)
cd app && npx next build             # 통과
```

**⚠️ 환경 함정 3가지:**
- **vitest `--pool=threads` 필수.** 기본 forks 풀이 이 샌드박스에서 죽는다.
- **`npm run lint 2>&1 | tail -1` 금지.** biome 에러가 위쪽에 뜨는데 푸터만 보인다.
- **vitest teardown segfault가 비결정적으로 요약 줄을 자른다.** 테스트는 통과한 것이다 —
  재실행하면 카운트가 보인다. 실패로 오인하지 말 것.

말했다. `AI_DRAFT_BANNER`가 액션 4섹션 전부에 붙어 "그대로 쓰지 말고 반드시 검토·수정
하세요"로 끝났다 — 행동을 제시하는 섹션이 제시하기도 전에 스스로를 부인했다.

- **og-stats 스코프 한정**(`web/og-stats.ts`) — `## 전체 신호` 블록만 파싱. 전역 첫-매치라
  앞 섹션 불릿에 오염될 수 있었다. `한 줄 요약`에 불릿을 추가하기 **전에** 방어벽부터 세움.
- **배너 재작성** — `> 📝 **규칙 기반으로 파생된 초안입니다(LLM 아님).** 검증 설계의
  출발점으로 쓰고, 실제 고객의 문장으로 교체하세요.` 경고는 보존, 부인 톤만 제거.
- **인터뷰 질문 배너 basis 분기 (사실오류 수정)** — `llm-prescriptions.ts:212-219`가
  `basis:"llm"`(실제 응답 이유 도출)로 만드는데 렌더가 무조건 heuristic이라 표기했다.
  `LLM_QUESTION_BANNER` 신설. **`추천 인터뷰`·`설문`·`랜딩`은 분기하지 않는다** —
  `llm-prescriptions.ts:225-227`이 heuristic fallback이라 기존 배너가 사실이다.
- **`whatThisAllows` 승격** — 부록 신뢰도 4층의 `허용되는 사용`을 `## 한 줄 요약`으로.
  표는 부록에 그대로 둔다(승격이지 이동 아님).
- **근거 앵커** — 액션의 대상 라벨을 `opportunitySegments`/`resistanceSegments`와
  `segmentLabel`로 조인해 `- ← 기회 세그먼트: 긍정 34.3% · 신뢰도 high`. **조인 실패 시
  생략**(패딩 타깃 `표본 최다 세그먼트`, 폴백 `전체 (세그먼트 미확정)`). 타입 변경 없음.

## 3. 유닛 테스트가 못 잡고 실물 렌더가 잡은 것 (재발 방지)

- **`generate.ts:205`가 `doNotTrustYet = marketJudgment.whatThisDoesNotAllow`.** 항상 같은
  문장이다. 둘 다 렌더하면 같은 줄이 두 번 나온다. **테스트는 두 `toContain`이 같은
  문자열이라 둘 다 통과했다.** → `아직 못 하는 것` 줄 삭제 + `not.toContain` 회귀 가드.
- **`AI_DRAFT_BANNER`는 5개 섹션이 공유한다.** "위 발견에서 파생"은 `추천 인터뷰`에서만
  참이다. 나머지는 `detectThemes(question)`·`choices` 유래다. 배너 문구에 유래를 쓰려면
  **그 배너를 쓰는 모든 섹션에서 참인지** 확인할 것. 없는 근거를 지어내면 안 된다.
- **항목별 `caution`이 배너와 따로 논다.** `prescriptions.ts`의 `caution` 문자열이 배너
  아래에서 옛 톤을 재도입할 수 있다. 배너만 고치면 반쪽이다.
- 교훈: **`npm run build && npm run report:demo > demo.md` 로 실물을 눈으로 볼 것.**
  (`tsx`는 의존성에 없다. `report:demo`는 `node dist/...`라 빌드가 선행돼야 한다.)

## 4. 샘플 리포트 — 세 번 쏴서 배운 것

라이브 API POST만이 유일한 재생성 경로다(로컬 `.env`에 TURSO 토큰 없음). 개편은
**저장된 md에 소급되지 않는다** — 신규 생성만이 라이브 검증 경로다.

| 시도 | 질문 | 결과 |
|---|---|---|
| emllQ_SRgS | 주 4일제 · 급여 10% 삭감 | 95% 거부, 세그먼트 0 |
| vggYyU-UrG | 통화 AI 자동 녹음·요약 | **100% 거부**(180/180 동일), 세그먼트 0 |
| **2khi1bDwJ4** | 장보기: 온라인 배송 vs 마트 방문 | **22%/78% 갈림** ✅ 현재 샘플 |

**`예/아니오` + 명백한 손익 = 페르소나마다 정답이 하나로 고정된다.** 분산이 0이면
세그먼트가 갈릴 수학적 여지가 없고, 앵커도 0개가 된다(코드가 옳게 동작한 결과다).
**A냐 B냐 선호형**이라야 갈린다.

⚠️ **온도 문제가 아니다.** `src/llm/openai.ts:41-47`은 `temperature`·`seed`를 보내지
않는다(OpenAI 기본 1.0). 그런데도 180개가 전부 같았다. 합성 패널의 저분산은 성질이다.

**→ 미해결 큰 주제:** 100%/0%를 뱉는 패널을 누가 시장의 대리로 믿겠는가. "독자가
유의미하다고 못 받아들인다"의 **진짜 뿌리가 여기일 수 있다.** 이번 세션은 표현 층을
다듬었을 뿐 이 층위는 손대지 않았다.

현재 샘플 `2khi1bDwJ4`: 온라인 배송 22%(11명) · 기회 `지역=수도권`(33명·긍정 34.3%·high),
`연령=30~34세` · 저항 `지역=비수도권`(27명·6.2%·high). 앵커 4종·배너 3종 전부 렌더된다.

## 8. 랜딩 카드는 하드코딩이다

`app/src/app/page.tsx`가 샘플 링크 3곳(`:23`·`:36`·`:49`)과 **카드 값 6개**(문구·숫자·막대
너비·기준 라벨)를 문자열로 박아둔다. 샘플을 바꿀 때마다 손으로 맞춰야 한다.

**분모가 카드마다 다르다** — 카드1은 페르소나 기준(`60명 중 11명`, 막대 18%,
"가상 응답 180개 기준"), 카드2는 응답 기준(`34.3%`, 막대 34%, "합성 패널 응답 기준").
섞으면 랜딩이 거짓말을 한다. 리포트에서 파생시키는 구조 개선은 미착수.
