# 범위 밖 질문 탐지 (설계) · 2026-07-08

## 문제

세그먼트가 하나도 승격되지 않은 리포트가 **무언가 알아낸 척한다.** 실제 라이브 리포트:

```
전체 신호:      🟢 consensus(합의) · 응답 분포: 끈다=180
쉬운 요약 카드: "반응이 뚜렷하게 부정적이에요" · "60명 중 0명이 켠다"
저항 세그먼트:  "이 규모(표본 소수)에선 세그먼트별 차이가 통계적으로 뚜렷하지 않았어요
                — 전체 방향(위)이 핵심 신호입니다. 세그먼트로 쪼개 보려면 표본을 키우세요."
```

세 문장 모두 문제가 있다.

- `consensus(합의)`는 독자에게 "시장이 동의한다"로 읽힌다.
- `반응이 뚜렷하게 부정적이에요`는 시장 판정을 주장한다.
- **`전체 방향(위)이 핵심 신호입니다`는 독자를 가장 방어하기 어려운 숫자로 안내한다.**
- `표본을 키우세요`는 이 경우 **틀렸다** — 표본을 600명으로 늘려도 전원 `끈다`다.

## 진단 (프로브 실측, 2026-07-08)

`temperature`·`seed`를 전송하지 않으므로 OpenAI 기본값 1.0이다(`src/llm/openai.ts:41-47`).
샘플러는 정상이다. 실제 `askChoice` 경로로 프로브한 결과:

```
극단 (25~29 1인 수도권)   장보기: 온라인 6/6   ← 개별 페르소나는 거의 결정적
경계 (40~44 3인 수도권)   장보기: 온라인 5/6   ← 경계선은 흔들린다
경계 (35~39 2인 비수도권) 장보기: 온라인 1/6
```

첫 토큰 확률(logprobs)로 본 페르소나 민감도:

| 질문 | young(25~29·1인·수도권) | old(60~64·2인·비수도권) |
|---|---|---|
| 통화 AI 자동 녹음 | 끈다 **99.83%** | 끈다 **99.87%** |
| 장보기 온라인/마트 | 온라인 배송 **100%** | 마트 방문 **99.99%** |

**각 페르소나는 개별적으로 거의 결정적이고, 다양성은 오직 속성에서 나온다.**
질문의 답이 census 축(연령·성·지역·가구원수·혼인)에 의존하지 않으면 모든 페르소나가
똑같이 답한다. 그때 100%/0%는 "시장의 합의"가 아니라 **"이 도구가 그 질문에 대해
아무 정보도 갖고 있지 않다"**는 뜻이다. 인구 분포가 답에 기여한 바가 0이므로,
전체 비율은 통계청 데이터가 아니라 **언어모델의 사전 판단**이다.

대조 실험으로 프롬프트 유도 가설은 기각됐다 — 페르소나 시스템 프롬프트를 제거하면
확신이 오히려 **떨어진다**(끈다 99.85% → 93.43%).

**이것은 버그가 아니라 설계 공백이다.** 도구는 이 상태를 탐지하지도, 알리지도 않는다.

## 판정 — 기존 필드만 사용

새 데이터 레이어를 추가하지 않는다(§4 "부풀리기 금지"). 이미 있는 세 배열로 삼분한다.

| 티어 | 조건 | 진실 | 현행 문구 |
|---|---|---|---|
| `segmented` | 승격 ≥ 1 | 갈렸다 | 정상 |
| `underpowered` | 승격 0, `weakSignals` ≥ 1 | 효과는 크지만(≥10%p) 유의하지 않다 | "표본을 키우세요" — **맞음** |
| `no-effect` | 승격 0, `weakSignals` 0 | 인구 축에서 10%p 이상의 차이가 없다 | "표본을 키우세요" — **틀림** |
| `unanimous` | `distribution` 단일 버킷 | 응답 전부 동일. 인구 분포 기여 0 | "consensus(합의)" — **거짓** |

`unanimous` ⊂ `no-effect`(만장일치 ⇒ 모든 효과 0 ⇒ weakSignal 0).

**실측 대조로 검증 가능하다.** 라이브에 세 리포트가 있다:
`vggYyU-UrG`(통화녹음, 180/180 동일) → `unanimous` ·
`emllQ_SRgS`(급여삭감, 57:3, weakSignal 3개) → `underpowered` ·
`2khi1bDwJ4`(장보기, 승격 4개) → `segmented`.

## 설계 원칙

**판정은 한 곳에만 둔다.** 본문(`render.ts`)과 카드(`web/easy-summary.ts`)가 각자
판정하면 한쪽만 고쳐졌을 때 서로 다른 말을 한다. 이 저장소는 같은 실패를 이미 겪었다
(배너는 고쳤는데 항목별 `caution`이 옛 톤을 재도입).

**단언을 게이트 임계보다 세게 하지 않는다.** 10%p는 의사결정 임계이지 진실의 경계가
아니다. `no-effect`를 "표본을 키워도 안 갈린다"고 단언하지 않고 "갈리지 않을 가능성이
크다"까지만 말한다.

**정직성 신호는 삭제하지 않는다.** 추가와 보정만 한다. 제거하는 문장은 딱 하나 —
거짓인 `전체 방향(위)이 핵심 신호입니다`.

## 변경 사항

### 1. `src/report/scope.ts` (신규, 순수 함수)

```ts
export type ScopeVerdict = "segmented" | "underpowered" | "no-effect" | "unanimous";

export function scopeVerdict(report: FounderInsightReport): ScopeVerdict {
  if (report.opportunitySegments.length + report.resistanceSegments.length > 0)
    return "segmented";
  const buckets = Object.values(report.overallSignal.distribution).filter((v) => v > 0);
  if (buckets.length <= 1) return "unanimous";
  if (report.weakSignals.length > 0) return "underpowered";
  return "no-effect";
}
```

`segmented`를 먼저 확인하는 것은 방어적 선택이다(만장일치인데 승격이 있는 데이터는
논리상 불가능하지만, 그런 입력이 와도 승격을 우선한다).

타입 변경 없음.

⚠️ **소급되지 않는다.** 렌더는 생성 시 한 번 돌고 결과 md가 DB에 굳는다
(`web/store.ts:50` — 저장 컬럼은 `md TEXT`뿐, 리포트 객체가 아니다). 따라서 이 변경은
**신규 리포트부터** 적용된다. 라이브의 `vggYyU-UrG`·`emllQ_SRgS`는 옛 md를 그대로
보여준다. 개편 확인은 새 리포트 생성으로만 가능하다.

### 2. `render.ts` — 네 곳

**(a) `## 한 줄 요약` 상단 배너** (`segmented`면 배너 없음)

- `unanimous`: 이 질문이 범위 밖임을 밝히고, 표본 전원이 같은 답을 했으므로 아래 비율은
  통계청 인구 분포가 아니라 언어모델의 사전 판단임을 명시한다.
- `no-effect`: 연령·성·지역·가구원수·혼인 어디에서도 10%p 이상 차이가 없었고, 이 질문의
  답은 인구 구성보다 다른 요인에 달려 있음을 밝힌다.
- `underpowered`: 배너 없음(표본 문제가 사실이므로).

**(b) `## 저항 세그먼트` 0개 문구를 삼분**

- `underpowered`: 현행 문구 유지.
- `no-effect`·`unanimous`: 10%p 이상 차이가 없었음을 밝히고, 표본을 키워도 이 축들로는
  갈리지 않을 **가능성이 크다**고 말한다. **`전체 방향(위)이 핵심 신호입니다`를 제거하고**
  전체 비율을 세그먼트 근거로 쓰지 말라고 명시한다.

**(c) `이 리포트로 할 수 있는 것` 보정**

`confidenceCard.marketJudgment.whatThisAllows`는 `"방향 가설 탐색 · 인터뷰 대상 좁히기"`다.
`segmented`가 아니면 **"인터뷰 대상 좁히기"가 거짓**이다. 원 문자열은 지우지 않고 뒤에
보정을 덧붙인다 — 세그먼트가 갈리지 않아 대상을 좁힐 수 없다는 사실.

**(d) `unanimous`일 때 전체 신호 라벨**

`🟢 consensus(합의)` 표시를 `⚪ 응답 전부 동일`로 바꾼다. **`signal` 필드는 건드리지
않는다**(집계 로직 무수정) — 표시만 바꾼다.

### 3. `web/easy-summary.ts` — 한 곳

`verdictSentence` 앞에 scope 분기를 둔다.

- `unanimous` → 이 질문이 이 도구의 범위 밖임을 말한다.
- `no-effect` → 인구 축에서는 갈리지 않았음을 말한다.
- 그 외 → 현행 `verdictSentence` 그대로.

`whoLine`(`"세그먼트 간 뚜렷한 차이는 없었어요."`)과 `next` 폴백은 이미 정직하므로
건드리지 않는다.

## 범위 밖 (YAGNI)

- **사전 프로브** — 생성 전에 대비 페르소나를 찔러 만장일치를 예측하는 방식. `unanimous`는
  잡지만 `no-effect`·`underpowered`(승격 0인데 응답은 갈림)는 예측하지 못한다. 사후 판정이
  어차피 필요하므로 이번엔 넣지 않는다. API·폼 UX·새 상태가 늘어난다.
- **OG 이미지** — `web/og-stats.ts`는 md를 정규식 파싱하므로 결합이 늘어난다(§8 함정).
  숫자만 뿌리므로 본문·카드보다 거짓이 덜하다.
- **temperature 조정** — 원인이 아니다. 올려봐야 신호가 아니라 잡음이 는다.
- **census 축 추가**(소득·직업·자녀) — 없는 데이터 레이어 추가는 "부풀리기"라 금지.

## 검증

TDD. 실패 테스트를 먼저 쓴다:

1. `scopeVerdict`가 4갈래를 정확히 판정한다(각 갈래 픽스처).
2. `unanimous` 렌더에 범위 밖 배너와 `⚪ 응답 전부 동일`이 있다.
3. `no-effect` 렌더에 `전체 방향(위)이 핵심 신호입니다`가 **없다**.
4. `underpowered` 렌더는 현행 표본 문구를 **유지**한다(과잉 적용 방지).
5. `segmented` 렌더에는 배너가 **없다**.
6. `segmented`가 아니면 `이 리포트로 할 수 있는 것`에 보정 문구가 붙는다.
7. **회귀**: `unanimous` 렌더에서도 `extractOgStats`가 `## 전체 신호` 값을 정상 파싱한다.
8. **회귀**: 모든 갈래에서 `아직 믿으면 안 되는 것`·`## 기술 상세 — 신뢰도 4층`·
   synthetic 고지가 남는다.
9. `easy-summary`가 `unanimous`·`no-effect`에서 시장 판정문(`반응이 뚜렷하게 …`)을
   내지 않는다.

게이트 4종: `npx vitest run --pool=threads` (⚠️ `--pool=threads` 필수) /
`npx tsc --noEmit` / `npm run lint`(전체 출력) / `cd app && npx next build`.

**실측 대조는 자동화할 수 없다.** `scopeVerdict`는 `FounderInsightReport` 객체를 받는데
DB에는 렌더된 md만 남는다(`web/store.ts:50`). 저장된 리포트를 함수에 먹일 수 없다.

대신 픽스처를 **관측된 라이브 md의 형태에 맞춰** 만든다. 관측 근거:

| 리포트 | 관측된 md 증거 | 기대 티어 |
|---|---|---|
| `vggYyU-UrG` | `응답 분포: 끈다=180` (단일 버킷), 승격 0, weakSignal 줄 0 | `unanimous` |
| `emllQ_SRgS` | 승격 0, `표본이 작아 우연일 수 있음` 줄 3개(연령 50~54·30~34·75~79) | `underpowered` |
| `2khi1bDwJ4` | 기회 2 · 저항 2 승격 | `segmented` |

(`vggYyU-UrG`의 `우연일 수 있음` 1건은 weakSignal이 아니라 **위험한 가정**의 문구
`7개 세그먼트가 minN 미만 — 우연일 수 있음`이다. weakSignal 줄은 `표본이 작아 우연일 수
있음` 접미사를 가진다. 픽스처 작성 시 혼동하지 말 것.)

배포 후 실물 확인은 **새 리포트 1건 생성**으로 한다(~$0.04, 관리자 토큰 필요).
만장일치가 잘 나오는 질문(예: 프라이버시 침해형 예/아니오)을 쓰면 `unanimous` 경로를
싸게 밟을 수 있다.
