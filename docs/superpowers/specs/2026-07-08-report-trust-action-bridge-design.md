# 리포트 신뢰–행동 다리 놓기 (설계) · 2026-07-08

## 문제

독자가 리포트를 읽고 **"이건 내게 유의미한 결과다"라는 결론에 도달하지 못한다.**
사용자 피드백으로 특정된 두 지점:

1. **정직성 신호가 역효과** — `신뢰도 low`·`우연일 수 있음`·`판단 보류`가 쌓여
   "결국 아무것도 모른다는 소리"로 읽힌다.
2. **행동이 이어지지 않음** — 숫자와 인터뷰 질문·7일 액션 사이의 연결이 약해
   "읽고 나면 달라지는 게 없다".

## 진단 — 둘은 같은 뿌리

현재 렌더는 **"믿지 마라"를 7회 이상 말하고, "이건 말할 수 있다"를 단 1회,
그것도 부록에서 말한다.**

| 위치 | 신호 |
|---|---|
| `render.ts:41` | `> ⚠️ disclaimer` |
| `render.ts:48-49` | `아직 믿으면 안 되는 것` 바로 다음 줄에 `이번 주 행동` |
| `render.ts:79` | 관심/거부 이유 배너 (v2에서 basis 분기 완료) |
| `render.ts:26` | 세그먼트마다 `- ⚠️ caveat` (샘플 기준 27줄) |
| `render.ts:166` | `## 추천 인터뷰 대상` + `AI_DRAFT_BANNER` |
| `render.ts:178` | `## 인터뷰 질문 초안` + `AI_DRAFT_BANNER` |
| `render.ts:186` | `## 설문 문항 초안` + `AI_DRAFT_BANNER` |
| `render.ts:194` | `## 랜딩 메시지 테스트` + `AI_DRAFT_BANNER` |
| `render.ts:217` | `허용되는 사용` 컬럼 — **유일한 해독제, 부록** |

`AI_DRAFT_BANNER`는 "그대로 쓰지 말고 반드시 검토·수정하세요"로 끝난다. 즉
**행동을 제시하는 네 섹션 전부가 제시하기도 전에 스스로를 부인한다.** 독자의
오독이 아니라 리포트가 문자 그대로 그렇게 말한다.

### 사실오류 1건

`llm-prescriptions.ts:212-219` — 인터뷰 질문은 `basis: "llm"`, 즉 패널의 **실제
응답 이유에서 도출**된다. 그런데 `render.ts:178`은 `basis`와 무관하게 "heuristic으로
생성된 추정 초안입니다"라고 붙인다. v2가 관심/거부 이유에 적용한 basis 분기
(`render.ts:74`)가 액션 섹션에는 적용되지 않았다.

`추천 인터뷰`·`설문`·`랜딩`은 실제로 heuristic이다(`llm-prescriptions.ts:225-227`이
`HeuristicPrescriptionGenerator`로 fallback). 이 셋은 배너가 사실과 맞다.

## 설계 원칙

**정직성 신호는 한 개도 삭제하지 않는다**(불변식 §6). 이 도구의 차별점이다.
문제는 신호의 존재가 아니라, 신호가 **못 하는 말만 하고 할 수 있는 말을 짝지어
주지 않는다는 것**이다. 정직성이 "무지의 고백"이 아니라 "정밀함의 손질"로 읽히려면
못 하는 말 옆에 항상 할 수 있는 말이 있어야 한다.

**없는 근거는 지어내지 않는다.** 앵커 필드가 없는 섹션에 앵커를 만들지 않는다.
없는 데이터로 근거를 만드는 것은 §4가 금지한 "부풀리기"다.

## 변경 사항

### 1. 인터뷰 질문 배너 basis 분기 (사실오류 수정)

```
questionsAreLLM = interviewQuestions.length > 0
              && interviewQuestions.every(q => q.basis === "llm")
  true  → LLM_QUESTION_BANNER
  false → AI_DRAFT_BANNER
```

`LLM_QUESTION_BANNER`: 패널이 실제로 답한 이유에서 도출된 질문임을 밝히고,
검증 초안으로 쓰라고 안내한다.

`추천 인터뷰`·`설문`·`랜딩`은 **분기하지 않는다** — heuristic이 사실이므로.

### 2. `AI_DRAFT_BANNER`를 "쌍"으로

경고는 유지하되 정체와 용도를 앞에 둔다.

- **현재**: `⚠️ AI 생성 초안 · 검토 필요 — heuristic으로 생성된 추정 초안입니다.
  그대로 쓰지 말고 반드시 검토·수정하세요.`
- **개편**: `📝 위 발견에서 규칙 기반으로 파생된 초안입니다(LLM 아님).
  인터뷰 설계의 출발점으로 쓰고, 실제 고객의 문장으로 교체하세요.`

"교체하세요"가 기존 "검토·수정하세요"의 경고를 보존한다.

### 3. "할 수 있는 것"을 본문으로 승격

`confidenceCard.marketJudgment`의 `whatThisAllows` / `whatThisDoesNotAllow`를
`## 한 줄 요약`에 노출한다. **순서가 핵심이다.**

```
현재: - 아직 믿으면 안 되는 것: {doNotTrustYet}
      - 이번 주 행동: {thisWeekAction}

개편: - 이 리포트로 할 수 있는 것: {marketJudgment.whatThisAllows}
      - 아직 못 하는 것: {marketJudgment.whatThisDoesNotAllow}
      - 아직 믿으면 안 되는 것: {doNotTrustYet}
      - 이번 주 행동: {thisWeekAction}
```

`doNotTrustYet`은 삭제하지 않는다. 신뢰도 4층 표도 부록에 그대로 둔다 —
**승격이지 이동이 아니다.**

### 4. 근거 앵커 — 세그먼트 수치를 조인해서만

단순히 세그먼트 *이름*을 다시 적는 것은 동어반복이다. `## 추천 인터뷰 대상`은
`### {targetLabel}`이 이미 세그먼트 이름이고, `## 랜딩 메시지 테스트`에는
`- 타겟: {targetSegment}`가 이미 있다.

없는 것은 **그 세그먼트의 수치**다. 렌더 시점에 `report.opportunitySegments` ·
`report.resistanceSegments`를 `segmentLabel`로 조인해 긍정률·신뢰도를 끌어온다.
타입 변경 없이 기존 데이터만 쓴다.

- `## 추천 인터뷰 대상`: `targetLabel` → 세그먼트 조인 → `- ← 기회 세그먼트: 긍정 100.0% · 신뢰도 high`
- `## 랜딩 메시지 테스트`: `targetSegment` → 동일 조인
- **조인 실패 시 앵커 줄을 생략한다** — 없는 근거를 지어내지 않는다
- `## 인터뷰 질문 초안`·`## 설문 문항 초안`: **세그먼트 대상이 없다 → 부착하지 않는다**

`reasonCount`는 필드가 아니라 driver rationale 문자열에 `(응답 이유 N건 기반)`으로
박혀 있다. 이를 정규식으로 되캐내지 않는다 — og-stats가 render md를 파싱하다 생긴
결합(§8)을 되풀이하지 않기 위함이다.

## 범위 밖 (YAGNI)

- **섹션 병합·발견→행동 단일 흐름 재구성** — `types.ts`·`generate.ts` 대수술이
  필요하고 게이트 판정 로직 인근을 건드린다. §6 불변식과 충돌. A 적용 후 새 샘플을
  보고 재평가한다.
- **캘리브레이션 성적표 상단 배치** — 사용자가 지목한 문제가 아니다. 사용자 생성
  리포트에는 fidelity 수치가 없다.
- **세그먼트 27줄 압축** — 별개 불만(분량)이며 이번 두 지점과 무관.

## 검증

TDD. 실패 테스트를 먼저 쓴다:

1. `interviewQuestions`가 전부 `basis:"llm"`이면 LLM 배너, 하나라도 heuristic이면 기존 배너
2. `추천 인터뷰`·`설문`·`랜딩`은 basis와 무관하게 `AI_DRAFT_BANNER` 유지
3. `한 줄 요약`에 `할 수 있는 것`이 `아직 못 하는 것`보다 먼저 나온다
4. `doNotTrustYet`이 여전히 렌더된다 (정직성 신호 보존 회귀)
5. `## 전체 신호` 헤더와 `응답 분포:` 줄이 그대로다 (차트 주입·og-stats 회귀)
6. **og-stats가 새 불릿에 오염되지 않는다** — 아래 "선행 불릿 위험" 참조
7. 앵커는 `추천 인터뷰`·`랜딩`에만, 인터뷰 질문·설문엔 없다

### ⚠️ 선행 불릿 위험 (설계 시 발견)

`web/og-stats.ts`의 세 정규식은 모두 `m` 플래그 **첫 매치**를 취한다:

```
:15  /^- .*?· 응답 분포: ([^\n]+)/m
:29  /^- n=(\d+)/m
:30  /^- 표본 \d+명 · 각 \d+회 응답\(총 (\d+)\)/m
```

변경 3은 `## 한 줄 요약`에 새 불릿 2줄을 추가하는데, **한 줄 요약은 `## 전체 신호`보다
앞에 온다.**

**위험도 정정 (조사 결과):** `marketJudgment.whatThisAllows`는 `confidence.ts:63`의
하드코딩 문자열("방향 가설 탐색 · 인터뷰 대상 좁히기")이고 `whatThisDoesNotAllow`는
`missingAxes` 축 이름으로 조립된다. **LLM이 채우지 않는다.** 따라서 실제로 깨질
확률은 낮다. 셋 중 `^- n=` 와 `^- 표본 \d+명 …` 은 불릿 접두가 고정이라 요약 불릿과
절대 매치되지 않는다. 유일하게 도달 가능한 것은 `^- .*?· 응답 분포: ` 뿐이며,
`.*?` 접두 와일드카드 때문에 요약 문구에 `· 응답 분포: `가 들어가면 매치된다.

그래도 고친다. **첫 매치 전역 스캔이 섹션 경계를 모른다는 결합 자체가 §8이 경고한
그 결합**이고, 하드코딩 문자열은 언제든 바뀐다. 대응은 정규식 강화가 아니라
**스코프 한정**이다 — `## 전체 신호` 블록을 잘라내고 그 안에서만 매치한다.
차트 SVG가 이 블록 안에 주입되므로(`pipeline`이 `## 전체 신호\n` 뒤에 삽입)
기존의 `^- ` 불릿 앵커는 그대로 유지해 aria-label 매치를 계속 피한다.

미끼 픽스처로 red-first 검증: `한 줄 요약` 불릿에 `· 응답 분포: 쓴다=1`을 심고
`extractOgStats`가 `전체 신호`의 값을 반환하는지 확인한다.

게이트 4종: `npx vitest run --pool=threads` / `npx tsc --noEmit` /
`npm run lint`(전체 출력 확인) / `cd app && npx next build`.
